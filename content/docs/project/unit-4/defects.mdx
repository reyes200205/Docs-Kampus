**[Nuevo]** Este es el registro formal de defectos para la Unidad 4. El detalle de cada uno (causa, solución y la prueba que evita que vuelva) está en [Errores resueltos](/docs/project/bug-log), que el equipo llena desde octubre en el mismo PR que trae el arreglo.

## Cómo se gestiona un defecto

1. **Se detecta** en una prueba automática, en la revisión de un PR, en una prueba manual o en el servidor.
2. **Se registra:** si es de una tarea abierta, se comenta en su PR; si no, se crea una tarea en Plane o se le avisa al responsable en Slack.
3. **Se corrige** en una rama `fix/...` con una prueba que falla sin el arreglo, cuando se puede.
4. **Se cierra** cuando el PR se fusiona en `develop`, y se anota en [Errores resueltos](/docs/project/bug-log) con el enlace al PR.

| Severidad | Criterio |
| --- | --- |
| **Crítica** | Expone datos personales, permite saltarse un control de seguridad o tira el servicio. |
| **Alta** | Una función principal no sirve o un grupo de usuarios no puede usar la app. |
| **Media** | Una función falla, pero hay forma de seguir, o el problema solo se ve en el servidor o en la CI. |
| **Baja** | Detalle visual, de texto o del entorno local. |
