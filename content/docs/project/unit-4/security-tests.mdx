**[Nuevo]** Cada control de seguridad de [Seguridad (OWASP)](/docs/project/unit-3/security) tiene al menos una prueba automática que corre en cada PR. Si alguien rompe un control, la CI se pone en rojo y el PR no se puede fusionar. Aquí están agrupadas por tema; los nombres son los de los métodos de prueba en [`tests/`](https://github.com/WilbertDevMx/backend-kampus/tree/develop/tests).

## Inyección SQL

**[Nuevo]** `SqlInjectionTest` (20 pruebas, [backend #86](https://github.com/WilbertDevMx/backend-kampus/pull/86)) ataca las dos consultas que arman SQL a mano con un texto del usuario: la búsqueda de cuentas del panel (`/api/admin/users?search=`) y el filtro de carrera de Descubrir. Cada una se prueba con seis cadenas de ataque: `' OR '1'='1`, `' OR 1=1 --`, `%' OR '1'='1' --`, `' UNION SELECT password FROM users --`, `'; DROP TABLE users; --` y `' OR 1=1 --`.

| Prueba | Qué comprueba |
| --- | --- |
| `SqlInjectionTest::test_the_panel_user_search_treats_sql_as_plain_text` (6 casos) | La búsqueda no devuelve a nadie, y la tabla `users` sigue ahí con las mismas cuentas. |
| `SqlInjectionTest::test_quotes_in_the_panel_search_are_searched_literally` | Buscar `o'con` encuentra a "Sinéad O'Connor": las comillas se buscan como texto. |
| `SqlInjectionTest::test_the_discovery_career_filter_treats_sql_as_plain_text` (6 casos) | El filtro se guarda tal cual y Descubrir solo muestra a quien tiene ese texto exacto en su carrera. |
| `SqlInjectionTest::test_sql_in_the_login_does_not_log_anyone_in` (6 casos) | Como correo o como contraseña, la cadena responde `422` y no crea ningún token. |
| `SqlInjectionTest::test_filters_with_fixed_values_reject_anything_else` | `sort`, `status`, `role` y `university_id` del panel solo aceptan sus valores y responden `422` con cualquier otra cosa. |
| `DiscoveryApiTest::test_the_career_filter_treats_wildcards_as_plain_text` | Un `%` o un `_` en el filtro de carrera se busca como texto, no como comodín de `LIKE`. |
| `DatabaseErrorResponseTest::test_api_hides_database_details` | Si algo falla en la base, la respuesta no revela host, consulta ni `SQLSTATE`. |

**Las pruebas sí detectan una inyección.** Para comprobarlo, se cambiaron a propósito, solo en local, las dos consultas para que pegaran el texto en el SQL en lugar de mandarlo como parámetro: **13 de las 20 pruebas fallaron**. Por ejemplo, `' OR '1'='1` devolvió a los 3 estudiantes y `' OR 1=1 --` rompió la consulta con un `500`. Con el código real pasan las 20.

## XSS

**[Nuevo]** `XssTest` (16 pruebas, [backend #86](https://github.com/WilbertDevMx/backend-kampus/pull/86)) guarda cinco cadenas de ataque en cada campo de texto libre: `<script>alert(document.cookie)</script>`, `<img src=x onerror=alert(1)>`, `"><svg onload=alert(1)>`, un enlace `javascript:` y un `<iframe>`.

| Prueba | Qué comprueba |
| --- | --- |
| `XssTest::test_a_chat_message_is_stored_and_returned_as_plain_text` (5 casos) | El mensaje se guarda y se devuelve igual, al mandarlo y en el historial. |
| `XssTest::test_the_profile_bio_and_name_are_returned_as_plain_text` (5 casos) | Lo mismo con el nombre y el "Sobre mí". |
| `XssTest::test_a_group_name_and_description_are_returned_as_plain_text` (5 casos) | Lo mismo con el nombre y la descripción de un grupo. |
| `XssTest::test_input_reflected_in_an_error_stays_inside_json` | Una ruta con un `<script>`, que el error `404` repite, sigue siendo JSON y no HTML. |

En cada respuesta revisan que salga como `application/json`, con `X-Content-Type-Options: nosniff` y `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`: así el navegador no la interpreta como HTML ni ejecuta nada de ella. La API no borra ni cambia el texto (eso dañaría lo que escribió la persona); la app lo muestra como texto, así que el `<script>` se ve como letras y no se ejecuta.

## CSRF, CORS, cabeceras y límites

| Prueba | Qué comprueba |
| --- | --- |
| `SecurityHardeningTest::test_cors_only_allows_the_configured_frontend` | Otro origen no recibe permiso de CORS. |
| `SecurityHardeningTest::test_api_responses_include_security_headers` | Las cabeceras de seguridad salen en toda respuesta. |
| `SecurityHardeningTest::test_hsts_is_only_sent_over_https` | HSTS solo por HTTPS. |
| `SecurityHardeningTest::test_api_is_rate_limited_per_user` | El límite general responde `429`. |
| `PasswordResetApiTest::test_requesting_links_is_rate_limited` | No se pueden pedir enlaces sin límite. |
| `SmsTest` y `SmsPasswordRecoveryTest` | Los códigos por SMS vencen, tienen intentos limitados y espera entre envíos. |

CSRF no aplica a esta API: no usa cookies de sesión, sino el token en `Authorization: Bearer`, y CORS no permite credenciales ([CSRF](/docs/project/unit-3/security#csrf)).
