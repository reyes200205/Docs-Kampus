## Ejemplo: F-02, inicio de sesión con dos pasos

`TwoFactorApiTest::test_login_asks_for_the_code_and_then_issues_the_token`:

1. Activa la verificación en dos pasos de un estudiante verificado.
2. `POST /api/login` con su correo, contraseña y el nombre del dispositivo. **Espera:** `200` con `two_factor_required: true`, un reto (`challenge_token`) que vence y **ningún token**.
3. `POST /api/login/two-factor` con el reto y un código incorrecto. **Espera:** `422` con "El código no es correcto.".
4. Repite con el código TOTP del momento. **Espera:** `201` con el token, su tipo, su vencimiento y el usuario; la sesión queda con el nombre del dispositivo.
5. Usa ese token en `GET /api/user`. **Espera:** `200`.
6. Intenta usar el mismo reto otra vez. **Espera:** `422`: el reto es de un solo uso.

`test_a_code_cannot_be_used_twice` comprueba además que el mismo código TOTP no sirva en un segundo inicio de sesión.

## Rendimiento dentro de las pruebas

Dos pruebas funcionales además miden que el flujo no se vuelva lento con muchos datos:

- `MessageApiTest::test_history_and_message_updates_stay_under_two_seconds_with_two_thousand_messages`: el historial de un chat con 2,000 mensajes responde en menos de 2 segundos.
- `DiscoveryApiTest::test_the_number_of_queries_does_not_grow_with_the_batch`: Descubrir hace el mismo número de consultas a la base para 1 que para 10 perfiles (sin el problema N+1).

## Cómo correrlas

```bash
php artisan test --filter=TwoFactorApiTest     # un flujo
php artisan test tests/Feature/Auth            # todos los de autenticación
```
