La API usa **Laravel Sanctum** con tokens personales (Bearer). La app obtiene un token al iniciar sesión y lo envía en cada petición protegida. Los tokens **expiran a los 7 días** (RNF-02).

El [registro](/docs/backend/api/auth/register) y la [recuperación de contraseña](/docs/backend/api/auth/password) tienen su propia página.
</Callout>

## Iniciar sesión

```http
POST /api/login
Accept: application/json
Content-Type: application/json

{
  "email": "ana.lopez@uttcampus.edu.mx",
  "password": "********",
  "device_name": "iphone-ana"
}
```

`device_name` es opcional y sirve para identificar la sesión (por defecto, `api`). El correo se compara sin importar mayúsculas ni espacios.

### Respuesta `201`

```json
{
  "token": "kampus_1|Xk3...",
  "token_type": "Bearer",
  "expires_at": "2026-10-22T18:00:00+00:00",
  "user": {
    "id": 1,
    "name": "Ana López",
    "email": "ana.lopez@uttcampus.edu.mx",
    "email_verified_at": "2026-10-01T18:00:00+00:00",
    "role": "student",
    "university_id": 1,
    "profile_completed": true
  }
}
```

**[Nuevo]** Los campos `role` y `university_id` se agregaron con T-40. Un administrador tiene `university_id` en `null`, porque ve todas las universidades.

**[Nuevo]** `profile_completed` (T-49) es `false` mientras el estudiante no termina su perfil: la app lo manda a completarlo por pasos antes de dejarlo usar Descubrir. Para el staff siempre es `true`. Ver [Perfil completo](/docs/backend/api/profile/profile#perfil-completo).

### Errores

| Código | Cuándo | Mensaje |
| --- | --- | --- |
| `422` | Faltan campos, la contraseña es incorrecta o el correo no existe. Los dos últimos casos dan **el mismo mensaje**, para no revelar qué correos están registrados. | `Las credenciales no son correctas.` |
| `403` | El correo todavía no se verifica (RF-01). | `Verifica tu correo institucional antes de iniciar sesión.` |
| `403` | **[Nuevo]** La cuenta está suspendida por moderación o es de staff desactivado (RF-15, [T-41](/docs/backend/api/admin/staff#desactivar-o-reactivar-una-cuenta)). Con la contraseña incorrecta se recibe el `422` de siempre, sin revelar la suspensión. | `Tu cuenta está suspendida.` |
| `429` | Hubo **5 intentos fallidos** con el mismo correo desde la misma IP. El bloqueo dura **15 minutos**, aunque luego se ponga la contraseña correcta. Un inicio de sesión correcto reinicia el contador. | `Demasiados intentos fallidos. Intenta de nuevo en 15 minutos.` |

Cada intento fallido y cada bloqueo se registran en `storage/logs/security.log`, con el correo enmascarado (`an****@uttcampus.edu.mx`).

## Enviar el token

```http
GET /api/user
Accept: application/json
Authorization: Bearer <token>
```

### Respuesta `200`

Solo trae los campos públicos del usuario (`UserResource`):

```json
{
  "data": {
    "id": 1,
    "name": "Ana López",
    "email": "ana.lopez@uttcampus.edu.mx",
    "email_verified_at": "2026-10-01T18:00:00+00:00",
    "role": "student",
    "university_id": 1,
    "profile_completed": true
  }
}
```

### Respuesta `401`

Sin token, con un token inválido o con uno que ya expiró:

```json
{
  "message": "Unauthenticated."
}
```

Las rutas de usuario requieren `auth:sanctum` y `verified`. Además, la API limita a **120 peticiones por minuto** por usuario (`429` si se pasa).

## Cerrar sesión

```http
POST /api/logout
Accept: application/json
Authorization: Bearer <token>
```

Responde `204` sin contenido. Revoca **solo el token de esa petición**: las sesiones en otros dispositivos siguen activas.

## Roles

| Rol | Quién es | Qué ve en la app |
| --- | --- | --- |
| `student` | Alumno que se registra con su correo institucional. | Descubrir, Cerca, Chats, Grupos y Perfil. |
| `moderator` | Staff de **una sola** universidad. Lo crea un administrador. | Solo el panel de administración: usuarios, reportes y grupos de su universidad. |
| `admin` | Staff con acceso a todas las universidades. Lo crea otro administrador. | El panel completo, incluida la gestión de staff. |

Los permisos se validan en la API con *Policies*: si un moderador pide datos de otra universidad, la API responde `403`, aunque la app no muestre esa opción. El staff no puede usar las rutas sociales (swipe, match, chat). El primer administrador se crea en el servidor con `php artisan kampus:create-admin` (T-40).
