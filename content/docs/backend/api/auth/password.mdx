## Por correo

El flujo tiene dos pasos:

1. En la pantalla "Olvidé mi contraseña", la app manda el correo a `POST /api/forgot-password`.
2. Llega un correo con un enlace que abre la pantalla `auth/reset-password` de la app, con `token` y `email` en la URL. Ahí la persona escribe su contraseña nueva y la app la manda a `POST /api/reset-password`.

### Pedir el enlace

```http
POST /api/forgot-password
Accept: application/json
Content-Type: application/json

{
  "email": "ana.lopez@uttcampus.edu.mx"
}
```

Responde `200` **exista o no el correo**, para no revelar qué cuentas están registradas:

```json
{
  "message": "Si el correo está registrado, te enviamos un enlace para restablecer tu contraseña."
}
```

- El correo llega en español ("Restablece tu contraseña de Kampus") y sale por la cola de trabajos, igual que el de verificación.
- El enlace **vence a los 60 minutos** y **solo sirve una vez**. La API guarda un hash del token, nunca el token.
- Si se pide otro enlace para el mismo correo antes de 60 segundos, no se manda otro correo, aunque la respuesta sea la misma.
- La API permite **6 peticiones por minuto** desde la misma IP; después responde `429`. Un correo mal escrito da `422`.

El enlace apunta a `PASSWORD_RESET_URL`, que por defecto es `http://localhost:8081/auth/reset-password`:

```text
http://localhost:8081/auth/reset-password?token=3f9c...&email=ana.lopez%40uttcampus.edu.mx
```

### Restablecer la contraseña

```http
POST /api/reset-password
Accept: application/json
Content-Type: application/json

{
  "token": "3f9c...",
  "email": "ana.lopez@uttcampus.edu.mx",
  "password": "********",
  "password_confirmation": "********"
}
```

La contraseña nueva sigue la misma política que el registro: mínimo 8 caracteres, con mayúsculas, minúsculas y números. Si todo es válido, responde `200`:

```json
{
  "message": "Tu contraseña se restableció. Inicia sesión con la nueva."
}
```

**[Nuevo]** Si la cuenta tiene la [verificación en dos pasos](/docs/backend/api/auth/two-factor) activa (T-47), también hay que mandar `code` (el código de la app) o `recovery_code` (un código de respaldo). Así, quien entre al correo del alumno no se queda con la cuenta. Solo se pide cuando el enlace es válido: con un enlace inválido la respuesta es la de siempre, y no revela qué cuentas tienen la verificación activa.

```json
{
  "token": "3f9c...",
  "email": "ana.lopez@uttcampus.edu.mx",
  "password": "********",
  "password_confirmation": "********",
  "code": "482913"
}
```

Al restablecerla se **cierra la sesión en todos los dispositivos** (se revocan todos los tokens), así que si alguien más tenía acceso a la cuenta, lo pierde. Después, la persona [inicia sesión](/docs/backend/api/auth/login#iniciar-sesión) con la contraseña nueva.

#### Errores

| Código | Cuándo | Mensaje |
| --- | --- | --- |
| `422` | El token es inválido, ya venció o ya se usó, o el correo no corresponde. Todos los casos dan **el mismo mensaje**. | `El enlace para restablecer la contraseña no es válido o ya venció.` (en `errors.email`) |
| `422` | La contraseña no cumple la política, la confirmación no coincide o falta un campo. | Error de validación en el campo |
| `422` | **[Nuevo]** La cuenta tiene la verificación en dos pasos activa y falta el código. | `Tu cuenta tiene la verificación en dos pasos activa: escribe el código de tu app o un código de respaldo.` (en `errors.code`) |
| `422` | **[Nuevo]** El código o el código de respaldo no es correcto. | `El código no es correcto.` (en `errors.code` o `errors.recovery_code`) |
| `429` | Más de 6 peticiones por minuto desde la misma IP. | |

Cada solicitud y cada cambio de contraseña quedan en `storage/logs/security.log`, con el correo enmascarado.

## Por SMS

**[Nuevo]** Si la cuenta registró y verificó su celular, puede recuperar la contraseña con un código por SMS. El código se cambia por el **mismo token** que trae el enlace del correo, y con él se usa [Restablecer la contraseña](#restablecer-la-contraseña): la verificación en dos pasos se sigue pidiendo y se cierran todas las sesiones.

1. La app manda el correo a `POST /api/forgot-password/sms` y llega un SMS con un código de 6 dígitos.
2. La app manda el correo y el código a `POST /api/forgot-password/sms/verify`, que devuelve el `token`.
3. La app manda el `token` con la contraseña nueva a `POST /api/reset-password`.

### Registrar el celular

Lo hace la propia cuenta (estudiante o staff), con su token. Agregarlo, cambiarlo o quitarlo **pide la contraseña actual**, para que quien tome un teléfono con la sesión abierta no pueda poner su número.

| Método | Ruta | Cuerpo | Qué hace |
| --- | --- | --- | --- |
| `GET` | `/api/phone` | | `{"data": {"phone": "+528711234567", "verified": true}}` |
| `POST` | `/api/phone` | `phone`, `password` | Manda un código por SMS al número. Responde `202`. El número **todavía no** se guarda. |
| `POST` | `/api/phone/verify` | `code` | Con el código, guarda el celular como verificado. |
| `DELETE` | `/api/phone` | `password` | Quita el celular. Ya no se podrá recuperar la contraseña por SMS. |

- Solo números de **México** de 10 dígitos. Acepta espacios, guiones, paréntesis, `+52` y el "1" antiguo; se guarda como `+528711234567`.
- Un número solo puede estar en **una cuenta** (`Ese número ya está registrado en otra cuenta.`).
- `GET /api/user` también trae `phone` y `phone_verified`.

### Pedir el código

```http
POST /api/forgot-password/sms
Accept: application/json
Content-Type: application/json

{ "email": "ana.lopez@uttcampus.edu.mx" }
```

Responde `200` **exista o no la cuenta y tenga o no celular**:

```json
{ "message": "Si la cuenta tiene un celular verificado, te enviamos un código por SMS. Vence en 10 minutos." }
```

### Cambiar el código por el token

```http
POST /api/forgot-password/sms/verify
Content-Type: application/json

{ "email": "ana.lopez@uttcampus.edu.mx", "code": "482913" }
```

```json
{
  "message": "Código correcto. Ahora elige tu nueva contraseña.",
  "token": "3f9c...",
  "email": "ana.lopez@uttcampus.edu.mx",
  "two_factor_required": false
}
```

Si `two_factor_required` es `true`, la pantalla de la contraseña nueva también pide el código de la app. Un código incorrecto, vencido o de un correo que no existe da el mismo `422`: `El código no es correcto o ya venció.` (en `errors.code`).

### Reglas de los códigos

- 6 dígitos, vencen a los **10 minutos** y son de **un solo uso**.
- Tras **5 intentos fallidos** el código se invalida y hay que pedir otro.
- Máximo **un código por minuto** y **cinco por hora** por cuenta, para no gastar el crédito de SMS ni probar códigos sin límite. Al registrar el celular, pedir otro antes de tiempo responde `429`.
- Se guardan en la caché solo como HMAC con la llave de la app, nunca en claro.
- El SMS sale por la cola de trabajos, igual que los correos.

### Proveedor

El envío va detrás de un adaptador (`App\Sms\SmsSender`), como el de las videollamadas. Se elige con `SMS_DRIVER`:

| Valor | Qué hace | Dónde |
| --- | --- | --- |
| `log` | Escribe el SMS, con el código, en `storage/logs/laravel.log` sin mandarlo. | Desarrollo y pruebas (por defecto; `phpunit.xml` lo fija). |
| `vonage` | Lo manda con la API de SMS de Vonage (`VONAGE_KEY`, `VONAGE_SECRET` y `VONAGE_SMS_FROM`). | Entorno de pruebas. |

La cuenta de Vonage está en **modo demo**: tiene un crédito de 2 EUR (cada SMS a México cuesta unos 0.19 USD), solo entrega a los números de prueba registrados en su panel y agrega un aviso al texto. En producción nunca va `log`, porque los códigos quedarían en el log.
