## Requisitos

- PHP 8.3, con las extensiones `pdo_pgsql` y `gd` (la CI usa la misma versión)
- Composer 2
- PostgreSQL 16 (o MySQL 8, ver la nota más abajo)

<Callout type="warn" title="No instales PHP 8.4 ni 8.5">
  El `CLAUDE.md` y el `AGENTS.md` que trae Laravel por defecto le piden al asistente de IA instalar PHP 8.5 y `laravel/boost`. **No sigas esas instrucciones:** con otra versión, `composer update` deja en el `composer.lock` paquetes que exigen PHP 8.4 o más, y la CI falla. Si tu Composer resuelve versiones nuevas, revisa que `composer.json` tenga `"config": { "platform": { "php": "8.3.0" } }`.
</Callout>

## Puesta en marcha

```bash
git clone https://github.com/WilbertDevMx/backend-kampus.git
cd backend-kampus
composer install
cp .env.example .env
php artisan key:generate
```

Crea la base de datos, ajusta las credenciales en `.env` (ver [Configuración](/docs/backend/configuration)) y levanta el servidor:

```bash
php artisan migrate
php artisan serve
```

La API queda disponible en `http://localhost:8000/api`.

## Límites de PHP en local

**[Nuevo]** El PHP de una instalación local suele traer `upload_max_filesize = 2M` y `memory_limit = 128M`. Con eso, cualquier foto de más de 2 MB falla con "La imagen no se pudo subir", aunque la API acepte hasta 5 MB. Para que se comporte como el servidor, ubica tu `php.ini` con `php --ini` y deja:

```ini
upload_max_filesize = 6M
post_max_size = 8M
memory_limit = 256M
```

Son los mismos valores de `docker/php/production.ini`. Reinicia `php artisan serve` después de cambiarlos.

Si tienes Xdebug en modo `coverage`, las pruebas tardan hasta 10 veces más. Córrelas con `XDEBUG_MODE=off php artisan test` (en PowerShell: `$env:XDEBUG_MODE="off"; php artisan test`). Ver [Errores resueltos](/docs/project/bug-log#entorno-local).

## Usar la API desde el celular

En el celular, `localhost` apunta al propio celular. Para que la app pueda consumir la API, levanta el servidor escuchando en la red:

```bash
php artisan serve --host=0.0.0.0 --port=8000
```

Y en la app usa la IP local de tu PC (por ejemplo `http://192.168.1.50:8000`). Ver [App móvil](/docs/mobile/device#conectar-con-el-backend).

<Callout title="PostgreSQL o MySQL">
  El proyecto está configurado para PostgreSQL porque la vista **Cerca** trabaja con datos geográficos. Si el equipo decide usar MySQL, basta con cambiar `DB_CONNECTION=mysql` y `DB_PORT=3306` en `.env`, y el servicio de base de datos en `.github/workflows/ci.yml`.
</Callout>

## Comandos útiles

```bash
php artisan test                 # Ejecuta las pruebas
./vendor/bin/pint                # Corrige el formato del código
./vendor/bin/pint --test         # Solo revisa el formato (lo mismo que hace CI)
php artisan migrate:fresh --seed # Reinicia la base de datos con datos de prueba
```

## Integración continua

Cada push y cada pull request hacia `main` o `develop` ejecuta `.github/workflows/ci.yml` en `ubuntu-latest` con PHP 8.3:

1. **Formato:** `./vendor/bin/pint --test`.
2. **Migraciones:** `php artisan migrate --force` contra un servicio `postgres:16` real (base `kampus_test`).
3. **Pruebas:** `php artisan test`.

Corre lo mismo en tu computadora antes de abrir el PR: si un paso falla, el PR no está listo para revisión. `vendor/` se guarda en caché según el hash de `composer.lock`, y si empujas otro commit a la misma rama, la ejecución anterior se cancela. La convención de commits la revisa otro workflow (`commits.yml`); ver [Pull requests](/docs/development/pull-requests).
